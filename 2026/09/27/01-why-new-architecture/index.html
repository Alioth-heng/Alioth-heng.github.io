01 为什么大模型越来越难训练？
Published in：2026-09-27 | category： 技术学习 DeepSeek 架构

先从一个问题开始

你可能听过这样的新闻：”某公司发布了 1000 亿参数的大模型”、”某模型有 671B 参数”。那你有没有想过——

为什么模型要做得这么大？又为什么不能无限地堆大？

这一篇不讲任何新技术，只把”问题”本身讲清楚。理解了问题，后面几篇的方案才显得顺理成章。

模型是怎么”学习”的？

Token（词元）：模型处理文本的基本单位。一个汉字、一个英文单词片段，都可能是一个 token。模型不是读”句子”，而是读一串 token。

参数（Parameter）：模型内部的数字旋钮。训练就是不断微调几百万到几千亿个旋钮，让模型预测下一个 token 越来越准。

flowchart LR A[输入文本] --> B[切成 Token] B --> C[Transformer 逐层加工] C --> D[预测下一个 Token] D --> E[和正确答案对比] E --> F[微调参数] F --> C

模型能力的来源基本就三样：参数够多（容量大）、数据够多（学得广）、算力够多（训练得动）。参数多 = 容量大，能装下更复杂的知识——这就是大家拼命堆参数的原因。

普通 Transformer 的三笔账

Transformer 是几乎所有大语言模型的骨架，它由几十层相同的结构堆叠而成，每层主要有两个部件：

  • Attention（注意力）：让每个 token “看”其他 token，建立上下文关系
  • FFN（Feed-Forward Network，前馈网络）：对每个 token 独立做一次”加工”，模型的大部分参数都堆在这里

现在算三笔账：

第一笔账：计算成本

参数越多、数据越多，训练需要的 GPU 小时就越多。这笔账是线性的还好办，问题是模型大了之后，训练不稳定的概率也上升（loss 突然飙升、需要回滚重来），一次大事故可能浪费几周的算力。

第二笔账：显存成本

训练时，除了模型参数本身，还要存储梯度和优化器状态（比如 Adam 优化器要为每个参数多存好几份数据）。一个 671B 的模型，参数 + 梯度 + 优化器状态加起来是参数量的好几倍，单卡显存根本装不下，必须切分到成百上千张卡上。

第三笔账：推理时的显存与带宽

训练是一次性的，推理（用户实际使用）是每天都发生的。推理时模型要”记住”当前对话的全部上文（第 06 篇细讲 KV Cache），上下文越长，显存压力越大。而且大模型推理时，瓶颈往往不是”算得慢”，而是数据在显存里搬来搬去太慢——这和 GPU 的 HBM（High Bandwidth Memory，高带宽显存）带宽直接相关。

flowchart TD A[参数越堆越大] --> B[训练算力成本上升] A --> C[显存放不下
需要大量 GPU 并行] A --> D[推理时显存/带宽压力上升] B --> E{怎么办？} C --> E D --> E E --> F[思路一：不每次都用全部参数 → MoE] E --> G[思路二：上下文不用原样全存 → MLA]

核心矛盾一句话版

模型要大才聪明，但每个 token 都要动用全部参数、全部上下文，太浪费了。

注意这里的关键词：“每个 token 都”。这就埋下了两个优化方向：

  • 每次计算，真的需要全部参数吗？—— 不需要 → MoE（稀疏激活）
  • 每次记忆，真的需要原样保存全部上下文吗？—— 不需要 → MLA（压缩保存）

DeepSeek 的回答

DeepSeek-V3 的做法可以概括成：用架构创新把”大模型”变得便宜。

  • 总参数 671B（容量拉满）
  • 但每个 token 只激活 37B（计算量像 37B 的小模型）
  • 训练全程只用了 2.788M H800 GPU 小时，按每 GPU 小时 2 美元估算约 557.6 万美元（官方技术报告口径，含预训练、长上下文扩展、后训练三部分）
  • 训练过程”remarkably stable”，没有出现过不可恢复的 loss spike，也没有回滚

这些数字后面几篇都会拆开解释。现在你只需要记住：省钱不是靠魔法，是靠架构设计。

⚠️ 常见误区

❌ “参数越多就一定越强”
参数是”容量上限”，不是”能力保证”。数据质量、训练方法、架构效率同样关键。一个设计糟糕的 100B 模型可能不如精心训练的 30B 模型。

❌ “671B 就是每次计算 671B”
这是本系列最重要的纠偏。671B 是总参数量（仓库里有多少货），每个 token 实际只用 37B（这次取了多少货）。下一章开始细讲。

❌ “推理瓶颈是算力不够”
很多时候恰恰相反：GPU 算力是过剩的，瓶颈在显存带宽——数据从 HBM 搬到计算单元的速度跟不上。这就是为什么”减少要搬的数据”（MLA）如此有效。

❌ “模型大 = 训练成本一定天文数字”
成本 = 参数量 × 数据量 × 单价。V3 证明：通过稀疏激活（MoE）和工程优化（FP8 混合精度训练等），671B 模型的训练成本可以压到几百万美元量级。

自测题：你真的理解了吗？

  1. Transformer 的每一层主要由哪两个部件组成？模型参数主要集中在哪个部件里？
  2. 为什么说”模型要大才聪明”有道理，但”大就一定强”不对？
  3. 训练时显存里除了模型参数还要放什么？为什么这会让显存压力成倍增长？
  4. 为什么说大模型推理的瓶颈常常是”搬数据”而不是”做计算”？
  5. V3 的 671B 和 37B 分别指什么？训练总成本大约是多少？

参考答案

  1. Attention（建立 token 之间的关系）和 FFN（对每个 token 做加工）；参数主要集中在 FFN。
  2. 参数决定容量上限，知识更复杂的问题需要更大容量；但能力还取决于数据质量和训练方法，容量只是必要条件之一。
  3. 梯度和优化器状态。优化器（如 Adam）要为每个参数存若干额外状态，总量可达参数本身的数倍，所以显存压力远不止”参数多大就占多少”。
  4. GPU 计算单元的速度增长快于显存带宽的增长；每生成一个 token 都要把大量权重和缓存数据从 HBM 读一遍，数据搬运跟不上计算速度，GPU 就在”等数据”。
  5. 671B 是总参数量，37B 是每个 token 实际激活的参数量；官方口径训练全程约 2.788M H800 GPU 小时、约 557.6 万美元（按 $2/GPU·小时估算）。
