03 MoE 的 Router 和 Expert 到底怎么工作？
Published in：2026-09-27 | category： 技术学习 DeepSeek 架构

上一篇建立了直觉，这一篇把 Router 内部发生的事情讲透——但仍然不堆吓人的数学。

Router 到底在做什么？

Router 本身是一个非常小的网络（一个线性层而已）。它的工作流程：

  1. 拿到当前 token 的表示向量（可以理解为这个 token 的”特征档案”）
  2. 和每个专家做一次打分运算，得到 256 个分数
  3. 取分数最高的 Top-K 个（V3 里 K=8）
  4. 被选中的专家分别处理这个 token，结果按分数加权合并
flowchart TD T[Token 表示向量] --> R[Router 线性层打分] R --> S[分数列表
E1: 0.1 E2: 2.8 E3: 0.5 E4: 1.9 ...] S --> K[选出 Top-8
E2 和 E4 入选] T --> E2[专家 2 处理] T --> E4[专家 4 处理] E2 --> W[按分数加权合并] E4 --> W W --> O[本层输出]

所谓 Top-K Routing（Top-K 路由），就是”只取前 K 名”的选拔规则。分数低过线的专家，这次完全不参与计算。

训练时 Router 是怎么学会”分诊”的？

Router 的打分参数一开始是随机的，它和专家一起被训练：

  • 如果 token 走了某个专家、模型最终预测变准了 → 这条”分诊路线”被强化
  • 如果走错了专家、预测变差 → 路线被抑制

几万亿 token 下来，Router 自然学会”什么 token 该找什么专家”。

两个关键设计问题

问题一：有的专家被挤爆，有的专家没人去，怎么办？

如果不加干预，Router 会逐渐形成”偏爱”——少数专家承接了绝大多数 token（富者愈富），其余专家得不到训练。这叫路由崩塌（routing collapse）。后果：

  • 被挤爆的专家超载，计算资源浪费在排队上
  • 没人去的专家参数白费，容量退化

解决思路是负载均衡（Load Balancing），V3 用的是创新性的 Auxiliary-Loss-Free（无辅助损失）策略：给每个专家加一个动态调整的小偏置项，只用来影响”谁入选 Top-K”，不影响计算权重——哪个专家最近接客太少，就悄悄给它加分送客，而不干扰模型本身的学习目标。（V3 还保留了一个权重极小的序列级均衡损失做兜底。）

问题二：专家太多放不进一张卡，怎么办？

专家要分布在很多张 GPU 上（专家并行）。这样 token 可能要跨 GPU 旅行才能找到自己的专家——这就引出了下一篇的通信问题。

从”细粒度”理解 DeepSeekMoE

传统 MoE（如 Mixtral）：专家少而大（比如 8 个大专家选 2 个）。
DeepSeekMoE：专家多而小（256 个小专家选 8 个）。

类比：8 个”大科室”选 2 个，不如 256 个”细分专科”选 8 个灵活——治疗”骨折+近视”的病人，可以精确地同时调骨科和眼科，而不必把整个”外科大科室”搬过来。论文指出这种细粒度设计带来更好的专家专精化和更强的性能。

⚠️ 常见误区

❌ “Router 是一个复杂的大网络”
恰恰相反，Router 通常就是一个线性层（一次矩阵乘法），参数量可以忽略不计。”聪明”的分诊是训练学出来的，不是靠 Router 自身复杂。

❌ “专家 = 领域，比如 1 号专家管数学、2 号专家管代码”
没有这样的分配表。专家的分化是训练中自发形成的，研究发现部分专家确实呈现可解释的功能偏好，但多数专家的分工是模糊的、重叠的。

❌ “每个 token 的 Top-8 专家在不同层都一样”
每一层都有自己的 Router 和专家。同一个 token 在第 10 层走的专家和在第 50 层走的专家毫无关系。

❌ “V3 的负载均衡靠丢弃多余的 token”
很多 MoE 实现会”丢 token”（超载了就直接扔），V3 依靠无辅助损失均衡策略，官方报告训练和推理都不丢弃任何 token。

自测题：你真的理解了吗？

  1. Router 的输入、内部操作、输出分别是什么？为什么说它”很小”？
  2. 一个 token 被 2 个专家以 3.1 和 2.5 的分数选中，最终输出大概怎么合成？
  3. 什么是”路由崩塌”？它为什么是有害的？
  4. V3 的无辅助损失负载均衡和传统辅助损失方法的思路有什么不同？
  5. DeepSeekMoE 的”细粒度”体现在哪里？为什么说细粒度专家组合更灵活？

参考答案

  1. 输入是 token 的表示向量；内部是和每个专家的一次打分运算（线性层）；输出是各专家的分数（据此选 Top-K 并作为合并权重）。它小是因为只是一层矩阵乘法，分诊能力来自训练而非结构。
  2. 两个专家的结果按分数加权平均（softmax 归一化后约为 0.55 和 0.45 的权重），分数高的贡献大。
  3. Router 的偏好自我强化，绝大多数 token 涌向少数专家，其余专家得不到训练和使用；结果是容量浪费、超载专家成为瓶颈、模型实际能力退化。
  4. 传统方法在训练目标里加”均衡惩罚项”，会与模型学习目标冲突、损害性能；V3 的做法是给每个专家一个只影响 Top-K 选拔、不影响计算权重的动态偏置，哪个专家冷门就上调其偏置，做到”均衡但不干扰学习”。
  5. 专家数量多、单个专家小（256 选 8），而非少数大专家（8 选 2）。小专家可以更自由地组合出所需的”知识配方”，例如同时精确调用”数学推理”和”代码语法”两种细分能力，专精度和灵活性都更高。
