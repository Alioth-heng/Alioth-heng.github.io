07 MLA：DeepSeek 为什么要重新设计 Attention？
Published in：2026-09-27 | category： 技术学习 DeepSeek 架构

承接上一篇的困境

MoE 把”计算”变便宜了，但 KV Cache 问题原封不动地留在那里：

  • V3 有 61 层、128 个注意力头、每头 128 维
  • 按传统 MHA 的存法，每个 token 每层要缓存 128 头 × 128 维 × 2（K 和 V）= 32768 个数字
  • 128K 上下文 × 61 层 → 每个请求的缓存高达几十 GB

MLA（Multi-head Latent Attention，多头潜在注意力）是 DeepSeek-V2 提出的答案（V3 延续）。它的目标只有一个：把 KV Cache 压缩一个数量级，而且尽量不牺牲模型能力。

先看前辈们怎么省

在 MLA 之前，社区已有两种省缓存的办法，先理解它们，才知道 MLA 聪明在哪：

flowchart TD MHA[MHA
每个头独立存 K 和 V] -->|太占显存| MQA[MQA
所有 Q 共享 1 份 K/V] MQA -->|省太狠，能力掉| GQA[GQA
Q 分组，每组共享 1 份 K/V] GQA -->|还是不够省| MLA[MLA
把 K/V 压缩成低维潜在向量]
  • MQA（Multi-Query Attention，多查询注意力）：所有头共用一份 K/V。缓存省到极致（1/128），但所有头挤一张桌子，能力损失明显
  • GQA（Grouped-Query Attention，分组查询注意力）：折中，每组 Q 共享一份 K/V（如 Llama 系列采用）

它们的共同思路：少存几份 K/V。这必然在”省显存”和”保能力”之间硬折衷。MLA 换了一个思路：不减少份数，而是把每一份本身变小。

核心类比：100 页笔记压缩成 20 页

普通 MHA 像是把每个 token 的全部 K/V 原样归档：128 个头各存一份完整记录。但 DeepSeek 观察到一个事实——

不同头的 K/V 之间高度冗余。 大量信息是重复的、可互相推导的。

既然如此，为什么不先”提炼摘要”、只存摘要？

几个术语登记：

  • Latent（潜在/隐式）：不直接存原始数据，而是存一个更小的中间向量，原始信息”蕴含”在它里面
  • 低秩压缩（Low-rank Compression）：认为 K/V 虽然名义上有几万个数字，但真实信息量小得多，可以被一个 512 维的向量近似承载
  • c_KV（KV 的潜在向量）：MLA 每层每个 token 唯一需要缓存的主体

MLA 的缓存账本

DeepSeek-V3 的实际数字（官方技术报告）：

项目 传统 MHA MLA（V3）
每 token 每层缓存的数字个数 32768（128 头 × 128 维 × 2） 576（512 潜在 + 64 位置键）
相对比例 1 约 1/57

那 64 的额外部分是什么？是携带位置信息的解耦键（decoupled RoPE key）。细节见下面的”诚实的复杂性”。

“压缩”到底省了什么？——三个层面

  1. 显存容量：缓存缩小约 57 倍，同样显存能同时服务多得多的长上下文请求（吞吐量、成本）
  2. 显存带宽：每生成一个 token，需要从 HBM 读的缓存数据缩小同样的比例——直接提升生成速度（回忆第 06 篇：推理是搬运密集型工作）
  3. 长上下文的可行性：上下文越长缓存越大，MLA 把”128K 上下文”从理论可能变成工程可行

诚实的复杂性：MLA 不是免费魔法

⚠️ “MLA 就是把 KV 压缩一下”是帮助你入门的类比，真实的 MLA 有更具体的数学结构，也有真实的代价。

代价一：额外的投影计算。 存的时候要”压缩”（下投影），用的时候要”还原”（上投影）。每一层都多了几次矩阵乘法。

代价二：位置信息的特殊处理。 Attention 里有一个给 K/Q 加”位置编码”的机制（RoPE，旋转位置编码）。麻烦在于 RoPE 的数学形式无法直接套在压缩后的潜在向量上——位置信息没法”藏”进摘要再无损还原。DeepSeek 的解法是把位置相关的部分拆出来，用一个小的、不压缩的解耦键单独携带 RoPE（就是账本里的 64 维）。所以缓存的是 512 + 64 = 576。

代价三：工程技巧。 直接实现 MLA 要”先还原 K/V 再做注意力”，把省下的搬运又浪费在计算上。推理框架会用”矩阵吸收”（matrix absorption）技巧，把还原矩阵合并进别的投影矩阵，跳过显式还原——这也是 MLA 实现比 MHA 复杂的原因。

收益侧的确认：V2 论文的消融实验显示，MLA 的能力不逊于甚至略优于完整 MHA，同时缓存远小于 GQA。这说明”压缩”确实保住了关键信息。

四种 Attention 对比总表

方法 每头缓存 K/V？ 核心思路 缓存大小 能力
MHA 每头各存完整 KV 不省 最大（基准） 最好（基准）
MQA 全部共享 1 份 极端共享 最小（1/头数） 损失明显
GQA 分组共享 折中共享 中等（组数分之一） 接近 MHA
MLA 不存 KV，存压缩潜在向量 低秩压缩 极小（约 1/57） 不逊于 MHA

一句话：MQA/GQA 是”少存几份”，MLA 是”每份本身瘦身”，前者是删文件，后者是压缩文件。

⚠️ 常见误区

❌ “MLA 只是简单删除了 KV Cache”
不是删除，是压缩。信息仍被保留（在潜在向量里），需要时投影还原。删除 = 滑动窗口那种丢上下文，MLA 不是。

❌ “MLA 压缩的是模型参数”
MLA 动的是运行时的 KV Cache（每个请求自己的临时数据），模型参数一个字节都没少。回忆第 06 篇：参数和缓存是两种完全不同的显存占用。

❌ “MLA 可以无限解决长上下文问题”
缓存缩小约 57 倍 ≠ 零。上下文继续增长，缓存依然线性增长，只是斜率小了 57 倍。极长上下文仍需要其他配套技术。

❌ “MLA 是为了省计算”
MLA 的主目标是省缓存（显存 + 带宽），为此它还多了投影计算（靠矩阵吸收等技巧弥补）。省计算是 MoE 的活儿——两者分工不同。

自测题：你真的理解了吗？

  1. V3 用 MLA 后，每个 token 每层缓存多少个数字？传统 MHA 是多少？压缩率大约多少倍？
  2. MQA 和 GQA 用什么思路省缓存？MLA 的思路和它们有什么本质区别？
  3. 为什么说”压缩”既省显存容量、又省显存带宽？（提示：回忆第 06 篇的”搬运密集型”）
  4. MLA 为什么还需要一个 64 维的”解耦键”？它携带什么信息？
  5. MLA 的三个代价是什么？DeepSeek 用什么技巧弥补计算开销？

参考答案

  1. 576 个（512 维 KV 潜在向量 + 64 维携带位置信息的解耦键）；MHA 是 128 头 × 128 维 × 2 = 32768 个；约 1/57。
  2. MQA/GQA 是”减少 K/V 的份数”（全部或分组共享），本质是删减；MLA 不减份数，而是利用 K/V 间的低秩冗余，把每 token 的全部 K/V 联合压缩成一个 512 维潜在向量，本质是压缩。
  3. 显存容量：缓存本身变小，同显存可并发更多请求；带宽：每步生成需从 HBM 读取的缓存数据同比变小，而推理瓶颈常在带宽而非算力，所以生成速度也提升。
  4. 因为 RoPE 位置编码的数学形式无法直接作用在压缩后的潜在向量上（位置信息无法被”摘要”后无损还原），所以把位置相关部分拆出来，用不压缩的小键单独携带。
  5. 额外的下/上投影计算；RoPE 与压缩不兼容需要解耦设计；实现复杂（需要矩阵吸收避免显式还原 K/V）。推理框架通过把还原矩阵合并进其他投影矩阵（吸收），跳过显式还原来弥补。
