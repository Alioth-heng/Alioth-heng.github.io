10 DeepSeek-R1：RL 如何让模型学会推理？
Published in：2026-09-27 | category： 技术学习 DeepSeek 架构

这是整套博客的核心篇。前面所有的铺垫——可验证奖励（第 08 篇）、GRPO（第 09 篇）——现在汇成一条主线。本篇全部事实以 DeepSeek-R1 官方论文（arXiv:2501.12948）为准。

起点：DeepSeek-R1-Zero

R1-Zero 是一次大胆的实验：DeepSeek-V3-Base 基座模型，直接上大规模 GRPO 强化学习——没有任何 SFT（监督微调）铺路。

flowchart LR B[DeepSeek-V3-Base
671B MoE 基座] -->|纯 RL：GRPO| Z[DeepSeek-R1-Zero]

它的训练设置极简（论文原文）：

  • 奖励只有两个规则项：
    • 准确率奖励：数学题对比最终答案、代码题跑测试用例
    • 格式奖励：要求把思考过程和答案放进规定的标签（<think>...</think>）里
  • 没有奖励模型（刻意回避 reward hacking）
  • 没有人类标注的思维链数据

涌现：训练过程中发生了什么

随着 RL 推进，官方记录了三个震撼的现象：

现象一：回答越来越长。 平均回答长度随训练稳步增长——模型自己发现”多想一会儿”能拿更多分，于是学会把思考链越拉越长，并在难题上分配更多思考。

现象二：推理行为自发出现。 没人教过，模型开始表现出：

  • 自我验证（Self-verification）：检查自己刚算的结果
  • 反思（Reflection）：中途推翻自己的思路重来
  • 长思维链（Long Chain-of-Thought）：多步、有条理的推导
  • 探索替代方案（”或者换个思路……”）

现象三：Aha Moment。 训练中期，模型在回答中突然出现了这样的输出：

“Wait, wait. Wait. That’s an aha moment I can flag here…（等等……我可以在这里重新审视问题）”

这句话成为整个项目最著名的注脚：优化压力下，模型自发学会了”重新审视自己”。

成绩单：R1-Zero 在 AIME 2024（美国数学邀请赛）上的 pass@1 从基座的 15.6% 提升到 71.0%（配合多数投票达 86.7%），一度追平当时的 OpenAI o1-0912。

但是：R1-Zero 有严重的”毛坯房”问题

官方论文明确列出了 R1-Zero 的缺陷：

  • 可读性差（poor readability）：思维链混乱、难以阅读
  • 语言混杂（language mixing）：中英文在同一回答里来回切换
  • （还有无休止重复等问题）

一句话总结：推理能力强，但表达是毛坯的。

正式版 R1：多阶段训练流水线

为了解决这些问题并进一步提升，R1 的完整流程是（论文 Figure 2）：

flowchart TD B[DeepSeek-V3-Base] -->|阶段1：冷启动 SFT
几千条高质量长思维链| S1[可读性良好的起点] S1 -->|阶段2：推理 RL
GRPO + 语言一致性奖励| S2[推理强化模型] S2 -->|阶段3：拒绝采样生成数据
60万推理 + 20万通用 SFT
注意：这一步重新从 V3-Base 开始| S3[能力全面的对齐模型] S3 -->|阶段4：全场景 RL
规则奖励 + 奖励模型| R1[DeepSeek-R1]

逐阶段解读：

  1. 冷启动（Cold Start）：用”数千条”高质量长思维链数据对基座做 SFT，让模型的输出格式和可读性先达标，再进入 RL——避免 R1-Zero 那种”毛坯思维链”从一开始就跑偏
  2. 推理 RL：和 R1-Zero 相同的 GRPO 流程，额外加入语言一致性奖励，压制中英混杂
  3. 拒绝采样 + SFT：用上一阶段的模型大量生成解题数据，只保留答对的（拒绝采样），整理出约 60 万条推理数据 + 20 万条写作/问答等通用数据；值得注意，这一步的 SFT 重新从 V3-Base 开始训练，而不是在 RL 模型上继续
  4. 全场景 RL：数学/代码等仍用规则奖励，开放任务引入奖励模型（有用性、无害性），完成对人类偏好的对齐

最终成绩（论文 Table 2）：AIME 2024 pass@1 79.8%、MATH-500 97.3%、GPQA Diamond 71.5%、Codeforces Elo 2029（超过 96.3% 的人类参赛者），整体对标 OpenAI-o1-1217。

附赠：蒸馏（Distillation）

R1 还展示了”把大模型的推理能力搬进小模型”：用 R1 生成的约 80 万条数据，直接 SFT 到 Qwen/Llama 系列的 1.5B~70B 小模型上（只 SFT、不做 RL）。结果：14B 的蒸馏版就能超越很多更大的模型，说明推理模式可以被”教”给小模型。

⚠️ 常见误区

❌ “R1 的推理能力全部来自 RL”
不完全。RL 涌现了推理行为，但冷启动数据塑造了思维链的”表达方式”，后期 SFT 注入了大量整理过的推理模式，全场景 RL 还对齐了人类偏好。官方论文和后续分析都强调：最终模型的推理风格受数据筛选影响明显，并非纯 RL 自发。

❌ “R1-Zero 失败了，所以被抛弃”
恰恰相反。R1-Zero 是成功的关键实验（证明纯 RL 可涌现推理），R1 的冷启动数据里就包含 R1-Zero 生成、经人工修正的思维链。它是”毛坯成功、精装交付”的关系。

❌ “R1 = V3 + 一点 RL”
R1 是四阶段多流程的产物（两次 SFT + 两次 RL），其中数据生成、拒绝采样、重新训练等工程细节同样关键。

❌ “蒸馏模型也要做 RL 才强”
论文的消融表明：对小模型，直接用大模型推理数据做 SFT 蒸馏，效果优于小模型自己做 RL。推理模式的”迁移”比”重训”更划算。

自测题：你真的理解了吗？

  1. R1-Zero 的奖励函数有哪几个组成部分？为什么刻意不用奖励模型？
  2. “Aha moment”指的是什么？它被官方视为哪类能力的证据？
  3. R1-Zero 的三大缺陷是什么？分别被 R1 流水线的哪个设计解决？
  4. R1 的四个训练阶段分别做什么？其中哪一步是”重新从 V3-Base 开始”的？
  5. R1 蒸馏小模型时为什么只用 SFT、不用 RL？

参考答案

  1. 准确率奖励（对答案/跑测试）+ 格式奖励（思考放规定标签内）；因为担心大规模 RL 下奖励模型被 reward hacking，刻意只用难以作弊的规则奖励。
  2. 训练中模型输出突然出现”等等，让我重新审视这个问题”式的自我反思行为，官方将其解读为 RL 驱动下模型自我进化、涌现反思能力的标志性时刻。
  3. 可读性差→冷启动 SFT 用高质量长思维链规范表达；语言混杂→推理 RL 加入语言一致性奖励；整体能力不足→后续拒绝采样 SFT 与全场景 RL 继续增强。
  4. ①冷启动 SFT（数千条长思维链）；②推理 RL（GRPO+语言一致性奖励）；③拒绝采样生成 60 万推理 + 20 万通用数据做 SFT（这一步重新从 V3-Base 开始训练）；④全场景 RL（规则奖励+奖励模型）完成对齐。
  5. 论文实验显示小模型直接模仿大模型的高质量推理数据（SFT）效果优于其自行 RL；RL 需要强大的基座探索能力，小模型自身探索效率低，而”继承”成熟推理模式更高效。
