第一章：使用 Ollama 在普通电脑上运行自己的本地AI大模型
Published in：2026-10-11 | category： 技术学习 AI 应用

这是《从0搭建属于自己的AI QQ机器人》系列的第一章。整套系列记录的是我——一个只会基本电脑操作、没有 Linux 基础的大学生——把一个能聊天的 AI 装进自己电脑、接进 QQ、最后让它开口说话的全过程。

我不会假设你懂任何术语。每出现一个新词，我都会先用大白话说一遍它”是干什么的”，再去碰它。

写在前面：我为什么要折腾这个

最开始只是因为好奇：那些能聊天的 AI，到底能不能跑在我自己的电脑上，不联网、不花钱、也没人看得到我说了什么？

查了一圈发现能，而且门槛比想象中低得多。于是就有了这个系列：

  • 第一章：让电脑本地跑起一个大模型（本篇）
  • 第二章：把这个模型接进 QQ，变成一个能聊天的机器人
  • 第三章：让它不仅能打字，还能开口说话

每一章都能独立跑起来，不用担心跟不上。

一、先搞懂：大语言模型到底是个什么东西

先别管什么神经网络、Transformer。你只需要知道一件事：

原理：大语言模型做的是一件特别朴素的工作——“给你一句话的前半段，猜下一个字该是什么”。

举个例子。你对它说：

它心里的计算是：在人类写过的海量文本里，”今天天气真不错，我们一起去”后面最常接的是什么？可能是”公园””逛街””吃饭”。它算出概率最高的那个，输出来。

然后，它把刚输出的那个字拼回句子末尾，再猜下一个字。如此循环。

** chatbot 之所以”能回答问题”，本质上就是这一个动作重复几百次。** 它并不是真的在”思考”，也没有一个数据库在查答案——它只是在一个字一个字地往下接，而因为它”读过”的东西足够多，接出来的话看起来就像人在回答。

理解这一点很重要，因为它能解释后面你会遇到的很多现象：

现象 真正的原因
它会一本正经地胡说八道 它不是在查事实，只是在接”概率上最像”的字
同一个问题每次答案不一样 每次都在概率里抽样，不是固定答案
问它长篇大论要等很久 一个字一个字生成，几百个字就是几百次计算
聊太久它会忘事 它能”看到”的上下文有长度上限

模型文件里存的，就是这些”概率”的参数。所以我们常说模型有多少”参数”——参数越多，它记住的规律越细，但也越占内存、跑得越慢。

二、为什么我要把它装在自己电脑上

市面上能聊天的 AI 一堆，为什么要自己装？把两种方式的账算清楚你就明白了。

云端 AI（比如网页版、App）

优点：

  • 模型大、能力强，动辄几千亿参数，不是个人电脑能跑的
  • 不需要你有任何硬件，有网就能用
  • 开箱即用，不用折腾

缺点：

  • 你说的每一句话都要发到别人的服务器上。聊天内容、你粘贴的代码、你的文档，全都会离开你的电脑
  • 通常要联网、可能要付费、可能限速
  • 服务说停就停，你没法控制

本地 AI（本系列的做法）

优点：

  • 数据完全不出本机。断网也能聊，这不是比喻，是真的可以拔网线
  • 想怎么改就怎么改：换个模型、调参数、接自己的程序，没人拦你
  • 一次部署，长期免费使用，没有调用次数限制

缺点：

  • 需要硬件撑着，主要是显卡显存
  • 能力不如最顶级的云端模型（毕竟你电脑上跑的是”小模型”）
  • 要自己折腾，会遇到各种环境问题

注意：选哪条路没有对错，只有合不合适。我的判断标准很简单——
如果只是想找个工具干活，用云端；如果想搞懂它到底是怎么跑起来的、或者聊天内容不想给别人看，那就本地。
我做 QQ 机器人选本地，理由很实在：机器人的每一条聊天内容都要过模型，全发到别人服务器上，我不太舒服。

三、Ollama 是什么：给”大脑”配一台播放器

现在我们知道模型是一堆参数文件。但光有一堆参数文件，电脑不会自己用它——你需要一个软件来加载它、调度显卡、接收你的输入、把生成的话吐出来。

这个类比最好记：

类比 现实中的东西 我们这里
内容 电影文件（.mp4） 模型文件（一堆参数）
播放它的软件 播放器（PotPlayer / VLC） Ollama
  • 模型 = AI 的大脑（内容本身）
  • Ollama = 运行这个大脑的软件平台（播放器）

Ollama 帮你把几件麻烦事全包了：

  1. 下载模型：不用去各种网站找文件、猜该下哪个版本，一条命令搞定
  2. 自动挑硬件：有 NVIDIA 显卡就自动用显卡，没有就退回 CPU，你不用配置
  3. 提供统一接口：装好后它会在本机开一个服务（默认 127.0.0.1:11434），你的程序只要朝这个地址发一句话，就能拿回 AI 的回答

第三点最关键——正因为有了这个统一接口，第二章我们才能把 QQ 机器人接上去。

整个流程长这样：

graph LR A["你说的话<br/>（文字）"] --> B["Ollama 服务<br/>127.0.0.1:11434"] B --> C["把模型加载进显存<br/>（第一次较慢）"] C --> D["模型逐字生成<br/>一个字一个字往外吐"] D --> E["拼成完整回答<br/>返回给你"] E -.->|"继续追问"| A

四、我的电脑能跑吗？先算一笔账

这是本地部署最硬的一道门槛，但算清楚就不神秘了。

我的实际环境：

项目 配置
系统 Windows 11
CPU Intel i5-14600KF
显卡 RTX 4060 Ti 8GB
内存 16GB
用的模型 Qwen3.5-4B

为什么选 4B，而不是更大的

模型名字里的”4B”指的是 40 亿（4 Billion）个参数。选它的三个理由：

  1. 参数小，塞得进显存。经过量化压缩后，这个模型实际只占 约 3.3GB，我的 8GB 显存装得下，还能留出余量给系统和其他程序
  2. 跑得动。小模型每次生成一个字的计算量小，我实测日常问答 1~10 秒出结果，聊天可以接受
  3. 中文能力不错。Qwen（通义千问）系列对中文的训练比较充分，日常对话不像有些模型那样”翻译腔”

原理：模型大小怎么换算成显存？
粗略记：显存占用 ≈ 参数量 × 每个参数占用的字节数。
模型通常会做”量化”（把高精度数字压成低精度，比如 4-bit）。Qwen3.5-4B 用的是 Q4_K_M 量化，约等于每个参数 0.5 字节多一点，4.2B × 0.8 ≈ 3.3GB，和我实际看到的 3.32GB 对得上。
所以选模型时先看显存：8GB 显存大概能舒服地跑 7B8B 以下的模型；只有 4GB 显存就看看 1B3B 的小模型；没有独立显卡也能跑纯 CPU，只是会慢很多。

一句话判断法：显存有多大，就选多大的模型。不确定的话，从小的开始试，跑得动再往上加。

五、动手：安装与配置

下面每一步我都说明”为什么这么做”，不要无脑复制。

5.1 安装 Ollama

去 Ollama 官网下载 Windows 版安装包，双击安装，一路下一步即可。

装完后它会在后台跑起来。验证一下（Windows PowerShell 或 CMD 都行）：

能打印出版本号就说明装好了。

注意：Ollama 默认安装位置在 C 盘。程序本体放 C 盘没关系（就几百 MB），真正要挪走的是模型文件（动辄几 GB），见下一节。

5.2 把模型挪出 C 盘（重要，别偷懒）

为什么：模型文件随便一个就 3~10GB，全堆在 C 盘，用不了多久系统盘就红了，而且重装系统时还会丢。这一步建议在下载第一个模型之前就做，省得事后搬家。

做法是设置一个系统环境变量 OLLAMA_MODELS，指向你想存放的目录。

Windows PowerShell（以普通用户身份运行即可，不需要管理员）：

或者用图形界面（不喜欢敲命令就走这条）：

  1. Win 键搜索”编辑系统环境变量” → 打开
  2. 点”环境变量”
  3. 在”用户变量”区点”新建”
  4. 变量名填 OLLAMA_MODELS，变量值填 D:\AI\Ollama\Models
  5. 一路确定，然后重新打开一个终端窗口（已有窗口读不到新变量）

我实际用的就是 D:\AI\Ollama\Models。设置完之后，下载的模型都会落在这里，C 盘干干净净。

注意：改完环境变量后，必须重启 Ollama 进程才会生效；如果还没装模型，那就更省事，直接开始下载即可。

5.6 让它开机自启

每次开机手动敲命令很烦。我用的是 Windows 自带的”任务计划程序”，做成开机自动启动。

图形界面步骤：

  1. Win 键搜索”任务计划程序” → 打开
  2. 右侧”创建任务”（不是”创建基本任务”）
  3. 常规页：名称填 Ollama，勾选”不管用户是否登录都要运行”可以按需要选，我用的是登录时运行
  4. 触发器页：新建 → 开始任务选”启动时” → 延迟 30 秒（避开开机高峰）
  5. 操作页：新建 → 程序填你的 ollama.exe 路径，参数填 serve
  6. 设置页：勾选”如果任务失败，按以下频率重新启动”（我设的重试 3 次，间隔 1 分钟）

我实际是写了一个 .bat 脚本交给计划任务去跑，好处是可以顺手加上”先检查端口是否已被占用””把日志写到固定文件”这些逻辑。这也是第三章会反复用到的套路。

注意：如果你写了 .bat 脚本，文件必须存成 GBK 编码 + CRLF 换行。我第一次就是用了 UTF-8 + LF，结果 cmd 把中文注释当成了乱码命令，任务返回 255 直接失败，而且连日志文件都没生成，排查了半天。这是我这个系列里踩得最莫名其妙的一个坑。

六、我踩过的坑（以及排查思路）

这一节比安装步骤更值钱。遇到问题时，按这里的顺序查。

坑 1：模型到底下载到哪了？C 盘怎么还是变小了

排查：

如果输出为空，说明环境变量没设置成功（或者你没重开终端）。设置好之后重新下载模型才会落到新位置——已经下载的需要手动移动，或者直接删了重下更省事。

坑 2：第一次运行特别慢，是不是坏了

不是坏了。两个原因：

  1. 模型加载：3GB 数据从硬盘读进显存，机械硬盘尤其慢
  2. 显卡初始化：第一次用 CUDA 要编译/加载计算库

判断方法：连着问两个问题，如果第二个明显快，说明就是首次加载开销，不用管。

坑 3：GPU 没用上，全靠 CPU 在硬扛

症状：回答一个字一个字往外蹦，慢得离谱；风扇狂转但显卡很闲。

排查（CMD）：

在回答生成的过程中再执行一次，看”利用率”那一栏。如果显卡利用率始终是 0%，说明模型跑在 CPU 上。

常见原因：

  • 没装 NVIDIA 驱动，或驱动版本太老
  • 显存不够，模型被切分到内存里跑了
  • 装的是 CPU 版 Ollama（重新从官网下最新版一般能解决）

坑 4：curl 命令卡住不动 / 连不上 11434

这是我本机最诡异的一个坑，值得一提：Windows 注册表里配置的代理指向了一个根本没在运行的代理程序，导致 curl 等工具在访问本机地址时也要先去连代理，然后卡死。

解决办法：访问本机服务时一律加上 --noproxy "*"：

原理：127.0.0.1 是”本机”地址，访问自己根本不需要经过任何代理。但很多工具会无脑读系统代理配置，于是”访问自己”这件事也被送去了代理。加上 --noproxy "*" 就是明确告诉它：这次请求不要走代理。凡是你访问本机服务（Ollama、后面的机器人框架、TTS 服务）出问题，先加这个参数试一次。

坑 5：模型回答是空的，什么都没输出

这个坑我卡了挺久。模型明明跑起来了，但返回内容一直是空的。

原因：我用的这个模型支持”先思考再回答”。它在正式回答前会先输出一大段内部的思考过程，而思考过程和最终答案共享同一个长度上限（max_tokens）。思考写得太长，把预算吃光了，最终答案一个字都没轮到输出。

解决办法：调用时显式关掉思考。以 Ollama 原生接口为例，"think": false；同时把输出长度上限给够（我给的 2048）。关掉之后延迟从十几秒降到一两秒，短对话的质量反而更稳定。

原理：这告诉你一件事——模型”卡住”和”输出为空”往往不是模型坏了，而是输出预算被别的东西吃掉了。遇到空输出，先想想这段输出里是不是混进了你不想要的东西（思考过程、格式标记、超长前缀）。

七、总结

到这里，你的电脑上已经有了一个完全本地、不联网也能聊天的大模型。回顾一下做了什么：

  1. 装了 Ollama（模型播放器）
  2. 用 OLLAMA_MODELS 把模型挪出了 C 盘
  3. 下载了 Qwen3.5-4B，并确认它跑在显卡上
  4. 用 HTTP 接口调用成功——这一步打通了程序和 AI 之间的路

这套做法适合什么人：

  • 想搞懂大模型到底怎么跑起来的人（本地部署能让你看见每一个环节）
  • 在意聊天隐私、不想把内容发给别人服务器的人
  • 想拿 AI 做自己的小项目（机器人、助手、工具）的人
  • 有一张还过得去的显卡（6GB 显存以上体验会好很多）

不太适合的：只是想找个工具提效、完全不想折腾环境的——直接用云端服务更划算。

排查问题的通用思路（比记命令更重要）

我这一路遇到的问题，排查顺序基本都是这个套路：

“两个程序之间的事，先确认它俩连上了没有”——这个思路在第二章会变得更加重要。
